🔐 Authentication

The ULHT Digital Credential Service uses OAuth 2.0 with JWT tokens for secure API access. All API requests must include a valid authentication token.

ℹ️ Tip: Use the /auth/token endpoint to obtain your access token. Tokens expire after 1 hour.

Getting an Access Token

POST /oauth/token Content-Type: application/x-www-form-urlencoded grant_type=client_credentials& client_id=your_client_id& client_secret=your_client_secret

Using the Access Token

Include the access token in the Authorization header of all API requests:

Authorization: Bearer your_access_token

🔐 Security Note

Keep your client credentials secure and never expose them in client-side code. Access tokens expire after 1 hour and must be refreshed.

🛡️ Kong API Gateway

All services are accessible via Kong API Gateway for centralized routing, rate limiting, and CORS.

💡 Recommended: Use Kong Gateway for all API requests. Base URL: http://localhost:8000/api/v1

Gateway Routes

  • /api/v1/students/* → Student Service (8084)
  • /api/v1/lusofona/* → Lusofona Service (8085)
  • /api/v1/credentials/* → Credential Service (8086)
  • /api/v1/fulfilment/* → Fulfilment Service (8087)

Gateway Features

  • Rate limiting (100/min, 1000/hour)
  • CORS configuration
  • Request/response transformation
  • Service discovery integration
  • Kong UI: http://localhost:8082

📄 Response Formats

All API responses follow a consistent JSON format with standard HTTP status codes.

Success Response

{ "success": true, "data": { "credentialId": "cred_123456789", "status": "ISSUED", "issuedAt": "2024-01-15T10:30:00Z", "expiresAt": "2029-01-15T10:30:00Z" }, "message": "Credential issued successfully" }

Error Response

{ "success": false, "error": { "code": "INVALID_CREDENTIAL", "message": "The provided credential is invalid or expired", "details": { "field": "credentialId", "reason": "Credential not found" } }, "timestamp": "2024-01-15T10:30:00Z" }

HTTP Status Codes

Code Description Usage
200 OK Successful GET requests
201 Created Successful POST requests
400 Bad Request Invalid request parameters
401 Unauthorized Missing or invalid authentication
403 Forbidden Insufficient permissions
404 Not Found Resource not found
500 Internal Server Error Server-side error

Rate Limiting

Kong API Gateway enforces rate limiting to ensure fair usage and system stability.

⚠️ Rate Limits (via Kong Gateway)

Per minute: 100 requests
Per hour: 1000 requests
Note: Rate limits apply to all routes through Kong Gateway

💡 Tip: Direct service access (bypassing Kong) is not rate-limited but is not recommended for production use.

Rate Limit Headers

The API includes rate limit information in response headers:

X-RateLimit-Limit: 100 X-RateLimit-Remaining: 95 X-RateLimit-Reset: 1642234567

Handling Rate Limits

When you exceed the rate limit, the API returns a 429 status code. Implement exponential backoff for retries:

// Example retry logic const delay = Math.pow(2, attempt) * 1000; // Exponential backoff await new Promise(resolve => setTimeout(resolve, delay));
